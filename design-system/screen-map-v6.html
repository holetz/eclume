eclume screen map

Version 6, with the product direction of 2026-09-26. eclume becomes per user, without an organization: open signup, library in time, automatic processing after recording and AI access through MCP. Each screen shows whether it stays as it is, changes, is new or goes away. Routes and quoted UI copy are the product's own pt-BR strings.

Direction set on 2026-09-26
  1. No organization or tenant: each user has their own space.
  2. Open signup, without an invite, with immediate use.
  3. Separate administration panel, with an admin login.
  4. The desktop app also imports files.
  5. Voice notes: a button or a voice command to start, automatic stop after silence.
  6. Library in time: monthly and weekly calendar and a running list, with collapsible filters on the right.
  7. Import is a modal over the library, not a page.
  8. No sharing of recordings.
  9. No live transcription.
  10. On receiving the audio, the server applies configurable preprocessing and then transcribes.
  11. After the transcription, if enabled, it fills title, tags, collections and other fields, each with a recorded rule of how it is identified.
  12. Summaries follow templates picked by the agenda type, detected by presets.
  13. Global confidentiality settings. Replaced by item 17.
  14. Imported audio is placed in time by the file metadata, with the user confirming the date.
  15. MCP server for the AI to query and manipulate eclume.
  16. The user defines their own fields and filling rules.
  17. Confidentiality leaves the flows: at signup, the user accepts a notice that they are responsible for asking consent from whoever they record.
  18. Client stops existing; collection lives alongside tag.
  19. The admin defines the initial set of agenda types and templates; each user adjusts their own.
  20. Audio preprocessing is adjusted only by the admin, in the panel.
  21. The desktop signs in with e-mail and password, without pasting a token.
  22. The signup acceptance is enough: there is no per-person voice consent.
  23. Signup without e-mail confirmation.
  24. The recording screen is centred on the summary; compact player and transcript collapsed by default.
  25. The summary can be edited by hand or adjusted through chat with the server agent, which reads the transcript only when it needs to.
  26. The desktop finds the server on its own, without the user typing an address.

Journeys

Dashed steps are new or change. Dotted steps happen on the server, without a screen of their own, and show to the user as status.

Create an account and start

anyone
Signup→ Accept the consent notice→ Empty library: import or download the app→ Desktop app /app-desktop→ Desktop finds the server→ Sign in with e-mail and password

Record a meeting

desktop
Meeting detected→ Recording→ Sync queue→ Automatic processing→ Recording ready in the library

Take a voice note

desktop
"Nova nota" button or shortcut or Voice command→ Recording the note, with a silence indicator→ Stops on its own after silence→ Automatic processing→ Note in the library

Import a file

web or desktop
Library → Import modal or Import on the desktop→ Date read from the file: confirm or correct→ Upload→ Automatic processing→ Shows on the right calendar day

Automatic processing

server, visible as status
Audio received→ Audio preprocessing→ Transcription→ Field filling→ Agenda type detected→ Summary by the type's template→ Ready

Review a recording

user on the web
Library in time→ Recording: summary up front→ Adjust the summary by hand or through chat→ Check the filled fields→ Open the transcript only to check or correct→ Export

Use it through AI

connected assistant
Access token /tokens→ Connect through MCP: instructions and scopes→ The AI searches, reads and changes recordings

Administer the platform

admin
Admin login→ Users→ Default preprocessing→ Transcription and agents→ Service health

Server discoverynew
no screen; feeds the first run

Decision screens, in order

Step 2: each one becomes an artboard in Claude Design with 2 or 3 variants built from the Eclume components. The order follows what the other screens inherit.

1Library in time

How does a recording show on the calendar, and which view opens by default?

  • A: week as an agenda, blocks as tall as the duration
  • B: month with dots per day, detail on clicking the day
  • C: running list grouped by day as the default, calendar as the alternative

It is the home screen and defines the recording card reused everywhere else.

2Summary-centred recording

Where does the adjustment chat go, and how does the collapsed transcript show?

  • A: summary in the centre, chat in a right column, transcript in a collapsed strip under the player
  • B: summary in the centre, chat as a request bar fixed below the summary, transcript in a side drawer
  • C: Summary and Transcript tabs, with the chat always visible on the side

It defines where the filled fields go, so it comes before the decision about them.

3Filled fields

How does the user tell what the AI filled from what they confirmed?

  • A: an "automático" badge on each field, gone on editing or accepting
  • B: a "Revise 4 campos sugeridos" strip with accept all
  • C: fields always editable, with an origin history on hover
4Import modal

How to ask for the date confirmation without blocking whoever imports several files?

  • A: date per file in a table, editable before sending
  • B: sends right away and asks for the confirmation later, in the library itself
5Voice note

What is the smallest visual feedback for someone recording a note without looking at the screen?

  • A: only the tray icon changes, and a notification at the end
  • B: a small floating window with the sound level and the silence countdown
6Desktop first run

What does a lay person see when opening the app for the first time?

  • A: server already filled in and only the e-mail and password fields
  • B: "Procurando o eclume na rede…" and the list of what it found, then the login
  • C: "Digite o código que aparece na web" (6 characters), without a login in the app

A is the happy path of whoever downloaded from the server itself; B and C are the ways out when the installer came from elsewhere.
