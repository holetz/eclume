# Glossary

The **single source for what a term means here**. One entry per term, in the same bullet syntax as
every `index.md`: the term linked to a full doc and a one-sentence definition, or the term in bold
with the definition when there is no doc.

**Resolving a term.** When a word, acronym or jargon of the repository is unclear, **look here
first** (`grep -i '<term>' docs/glossary.md`). With no entry, the term has not been defined yet —
record it with `/quenching:knowledge:define`.

**This file is the deliberate exception to "one concept per file"**: a flat list, sorted
alphabetically by the English term, with one sentence per definition and a link out instead of an
explanation. An entry **without a link** (a term with no doc of its own) is a valid, permanent state.

**Canonical terms and UI labels.** The English term is the one every artifact uses. Where the
product shows a term to the user, the entry ends with `pt-BR UI label: "<label>"`; the pt-BR
catalogs are built from those labels. Labels and quoted UI strings are product text, not
translation targets of this glossary.

## Terms

- [access token](standards/code/server-mcp-e-dispositivos.md#scope-groups-of-the-mcp-connection-screen) — The PAT as the screen names it: created by the person under MCP Connection, with scope groups and an expiry, for an assistant or another program to use eclume on their behalf. pt-BR UI label: "Token de acesso".
- [adjustment chat](standards/code/server-agentes.md#adjustment-chat) — A conversation in which the user asks for a change to the summary and the chat agent replies, reading the transcript only when the request depends on what was said; a reply that changes the summary becomes a `chat` version. pt-BR UI label: "Chat de ajuste".
- [admin account](standards/code/server-admin.md) — An account of the `admins` table, separate from user accounts, with its own login and session (`/admin/auth/login`) that only reach `/admin/*`; created by the CLI `eclume-server admin create`.
- [admin panel](standards/code/frontend-web.md) — A separate app inside the web (`/admin/entrar`, `/admin/*`), with its own login, session and frame, where the admin account configures the platform without seeing user content. pt-BR UI label: "Painel de administração".
- [agenda type](standards/code/processamento-automatico.md) — A recording category defined by the user (team meeting, 1:1…) with a fill rule, a title pattern, default tags and the summary instructions; the agent detects the type after transcription. pt-BR UI label: "Tipo de agenda".
- [agent](standards/code/server-agentes.md) — A language model the server calls through a provider to fill fields, detect the agenda type, summarize and chat (the adjustment chat and the Agent screen). pt-BR UI label: "Agente".
- [Agent action](standards/code/server-agentes.md#agent) — A batch change the Agent proposes (regenerate summaries, apply or remove tags, add to or remove from collections, switch the agenda type) and runs only after the person confirms it on the card; each one is stored in `agent_actions`, which is also the audit log. pt-BR UI label: "Ação do Agente".
- [Agent conversation](standards/code/server-agentes.md#agent) — A session stored in Postgres under the owner's RLS (`agent_sessions`), with the questions, the answers and the input and output files, which the person resumes, renames or deletes under Conversations (`/agente/conversas`). pt-BR UI label: "Conversa".
- [Agent screen](standards/code/server-agentes.md#agent) — The web chat screen (`/agente`, formerly Questions and `/perguntas`), a highlighted navigation item that answers about the recordings and attached files, returns files to download and keeps conversations per user. pt-BR UI label: "Agente".
- [agent worker](standards/code/server-agentes.md) — The arq worker of the `server` package (`AgentWorkerSettings`, queue `eclume:agents`), which `eclume-server worker` runs in the `worker` service next to the `eclume:default` queue, and which runs the agent jobs — agenda type, fields, summaries, chats and previews — with `ECLUME_AGENT_MAX_JOBS` slots.
- [Anarlog](project/referencias.md) — A meeting-notes app (Tauri 2, MIT) from which the eclume desktop reuses Rust crates for audio detection and capture.
- [audio time](standards/code/desktop-gravacao.md#pausa-tempo-de-áudio-e-nível) — The recorded time without the pauses: the clock of the recording screens, the `at_ms` of the markers and the `duration_ms` of the upload. pt-BR UI label: "Tempo de áudio".
- [auto collection](standards/code/processamento-automatico.md#fill_fields) — A collection with a rule ("Quando incluir") and "Incluir automaticamente" on: after transcription, the agent adds to it the recordings that meet the rule, reading the conversation, the agenda type and the participants. pt-BR UI label: "Coleção automática".
- [automatic assignment](standards/code/identificacao-por-voz.md#automatic-assignment) — The speaker-to-person link made by voice at ingestion, before the summary, when the score passes the threshold the user configures on the account; it is flagged (`auto_score`), can be undone and only reinforces the voiceprint once confirmed.
- [awaiting speakers](standards/code/processamento-automatico.md#speaker-naming) — The state of a recording whose `speakers` step stayed `waiting` because the account requires speaker naming and there is a voice with no person; the agent chain only proceeds when the person names the speakers or picks "Seguir sem nomear" (on the desktop, "Precisa de você"). pt-BR UI label: "Aguardando locutores".
- [CA fingerprint](standards/code/server-mcp-e-dispositivos.md#ca-pinning-by-the-apps) — SHA-256, in hex, of the DER of the Caddy root certificate published at `/downloads/eclume-root.crt`; the apps check it to pin that root without installing it in the system.
- [collection](standards/code/server-nucleo.md) — A grouping of a user's recordings (by client, project or program); a recording can be in several. pt-BR UI label: "Coleção".
- [consent notice](standards/code/server-nucleo.md) — A versioned text the person accepts at sign-up ("Sou responsável por pedir o consentimento das pessoas que gravo"), in place of per-person voice consent; a new version asks for a new acceptance at login. pt-BR UI label: "Aviso de consentimento".
- [contract v1](standards/api/contrato-v1.md) — The OpenAPI and the transcription JSON Schema in `contracts/`, the source of truth between eclume and the clients; it only evolves additively, with the 2.x line under `/api/v1` (from the end of the organization work, 2.0.0, until the end of the redesign) as the single exception; the next break goes to `/api/v2`.
- [CPU worker](standards/code/server-nucleo.md) — The `worker` service (`eclume-server worker`, of the `server` package): the process that consumes the `eclume:default` queue, where it ingests transcripts from the GPU worker, runs the reaper and the resume and discards expired uploads, and the agent worker's `eclume:agents`.
- [date origin](standards/code/server-nucleo.md#recording-date-kind-and-markers) — Where a recording's start came from (`recorded_at_source`): `capture` (the app clock), `file_metadata` (file metadata, confirmed at import), `user` (typed) or `upload` (upload time).
- [default agenda type](standards/code/server-admin.md) — An agenda type maintained by the admin on the platform and copied to each new account at sign-up. pt-BR UI label: "Tipo de agenda padrão".
- [desktop import](standards/code/desktop-importacao.md) — An audio or video file brought into the desktop app by the dialog or dragged onto the window, with the date read from the file and confirmed, converted to Ogg/Opus (or copied as is) and uploaded with `source: upload`.
- [device credential](standards/code/server-mcp-e-dispositivos.md#device-credential) — An `eclp_` token of `kind: device` (with the device platform, `recordings:read` and `recordings:write`, no expiry) that the desktop or the phone receives when signing in by e-mail and password or by pairing code; revoking it switches the device off.
- [device state](standards/code/frontend-web.md) — How the desktop and the phone name a recording before and during upload (Gravando, Aguardando envio, Enviando, Enviada, Interrompida, Falhou o envio), through the shared vocabulary `vocabulario.js`. pt-BR UI labels: as listed.
- [diarization](standards/code/processamento-automatico.md) — Splitting a recording into per-speaker segments ("who spoke when"), done on the GPU worker by pyannote.
- [discovery (mDNS)](standards/code/server-mcp-e-dispositivos.md#network-discovery-mdns) — The `_eclume._tcp` announcement on the LAN by the `mdns` service (`eclume-server announce`), with the public URL and the CA fingerprint in the TXT record, so the apps find the server without typing the address.
- **eclume** — A self-hosted institutional transcription service (eco + lume), extracted from lumea and tied to it only by an API contract.
- [eclume Design System](standards/code/web-design-system.md) — The visual base of the three clients, versioned in `design-system/` (tokens, classes, components and the v6 map screens, exported from Claude Design): its `styles.css` generates, through `design-system/sincronizar.py`, the `eclume.css` copies of the web, desktop and mobile.
- [eclume network](standards/code/mobile-app.md#rede-do-eclume-e-sync) — The state of the mobile app in which it may sync: unmetered Wi‑Fi and `GET /api/v1/server` answering through the pinned CA with the same fingerprint; outside it, nothing leaves over mobile data. pt-BR UI label: "Rede do eclume".
- [eclume_pt](standards/code/server-nucleo.md) — The Postgres text-search configuration: `portuguese` with `unaccent` before the stemmer, used in the `tsvector` of the segments.
- [edge](project/deploy-producao.md#stack) — The `caddy` service of the compose (image `eclume-edge`, `deploy/web.Dockerfile`): Caddy with TLS on 8443, the server routes and the embedded SPA, with its rules in `deploy/web.Caddyfile`.
- **engine** — An implementation of the ASR interface of the `eclume_engines` package (`whisperx-local`, remote OpenAI-compatible, or CPU for dev).
- **epic** — An orchestrating spec (`holetz/eclume#1`) whose tasks point to child specs, each one its own issue.
- [fallback agenda type](standards/code/processamento-automatico.md#agenda-types) — Each account's agenda type ("Geral", with the "Padrão" badge in the screen) that cannot be deleted and keeps the recording when no other type fits with confidence (below 0.6), when there are no other types, no detection agent or the detection fails. Not to be confused with the admin's default agenda types. pt-BR UI label: "Geral" (badge "Padrão").
- [ffmpeg.wasm](standards/code/formato-audio-upload.md) — ffmpeg compiled to WebAssembly, the browser conversion fallback for containers and codecs WebCodecs does not cover.
- [field](standards/code/processamento-automatico.md) — A piece of data of a recording that the user defines (text, list or choice), with a fill rule; title and tags are the built-in fields of every account. pt-BR UI label: "Campo".
- [fill rule](standards/code/processamento-automatico.md) — The "how to identify" of a field: the instruction the agent follows to fill it from the transcript. pt-BR UI label: "Como identificar".
- [filter panel](standards/code/frontend-web.md#library-timeline) — The collapsible `.filters` on the right of the library (type, status, tags, people, collections and user fields), whose filters go in the URL and the query. pt-BR UI label: "Filtros".
- [first run](standards/code/desktop-deteccao-e-sync.md#primeira-execução-descoberta-e-ca-fixada) — The desktop app's "Bem-vindo" screen with no credential: the installer's server, found on the network or typed, the CA pinned by fingerprint and sign-in by e-mail and password or pairing code. pt-BR UI label: "Bem-vindo".
- [global shortcut](standards/code/desktop-interface.md#atalhos) — A key combination the desktop app registers system-wide to record, start a note and mark, `Ctrl+Alt+R/N/M` on Windows and Linux and `⌘⇧R/N/K` on macOS, changed in Settings · Audio.
- [GPU host](project/host-setup.md) — The server `192.168.15.199` (GTX 1660 Super, 6 GB) where the eclume and lumea containers run, reached through `docker --context gpu-host`.
- [GPU worker](standards/api/jobs-transcricao.md) — The arq process of the `worker-gpu/` pillar that runs ASR, alignment, diarization and embeddings in a single CUDA process.
- [GPU worker heartbeat](standards/api/jobs-transcricao.md) — The `eclume:gpu:health` hash that the GPU worker rewrites every 15 s (TTL 45 s) with the GPU, the resident model and whether there is a job; the admin panel's Health reads from it.
- [help article](standards/code/web-central-de-ajuda.md#o-cabeçalho) — A Markdown file at `web/src/features/help/articles/<slug>.md`, with a header (title, topic, page keys, related, terms, order, date), served at `/ajuda/<slug>`. pt-BR UI label: "Artigo de ajuda".
- [help center](standards/code/web-central-de-ajuda.md) — The user's help in the web (`/ajuda`): articles that live in the build, six topics, frequently asked questions and local search, with no server. pt-BR UI label: "Central de ajuda".
- [help drawer](standards/code/frontend-web.md) — The `.help-drawer` side panel of the web, opened with `?` or by the Help button in the page header, with that page's help links and the keyboard shortcuts. pt-BR UI label: "Ajuda".
- [help hint](standards/code/web-central-de-ajuda.md#busca-gaveta-e-dica) — The "?" (`HelpHint`) next to a rule that is not obvious on screen, which opens a short popover linking to the article.
- [help page key](standards/code/web-central-de-ajuda.md#o-cabeçalho) — The name of a screen (`pessoas`, `campos`, `mcp`…) that it declares with `useHelpTopic` and that articles list in `paginas`, so the drawer shows "Nesta página".
- [import queue](standards/code/frontend-web.md#import-modal-and-queue) — The files chosen in the Import modal, converted and uploaded one at a time by the shell, which survive closing the modal and navigating. pt-BR UI label: "Importar".
- [job contract](standards/api/jobs-transcricao.md) — The agreement between the server and the GPU worker: arq queues `eclume:gpu`/`eclume:default`/`eclume:agents`, the `transcribe` job, artifacts in the bucket and `ingest_transcript`/`transcription_failed`.
- [library timeline](standards/code/frontend-web.md#library-timeline) — The home screen of the web: recordings on the calendar (week as an agenda, month and list), positioned by start and duration. pt-BR UI label: "Biblioteca".
- **lumea** — A human and organizational development platform that imports eclume transcripts by PAT.
- [marker](standards/code/server-nucleo.md#recording-date-kind-and-markers) — An instant of a recording (`at_ms`), with an optional note and the device that marked it, sent by the apps idempotently by `client_id`. pt-BR UI label: "Marcador".
- [MCP server](standards/code/server-mcp-e-dispositivos.md#mcp-server) — The eclume Model Context Protocol at `/mcp`, in the server process, stateless and Bearer `eclp_` only: tools for an assistant to search, read and edit recordings, summaries and fields, each with the token's scope. pt-BR UI label: "Conexão MCP".
- [Mediabunny](standards/code/formato-audio-upload.md) — A TypeScript library for demux, conversion and mux over WebCodecs, the main path of media conversion in the browser.
- [mobile app](standards/code/mobile-app.md) — The eclume Android app (Tauri 2, `mobile/` pillar): a portable microphone that records with the screen locked, marks instants and syncs on the server's Wi‑Fi, without reading transcripts. pt-BR UI label: "eclume" (app).
- [mock server](../contracts/README.md) — Prism serving the contract v1 bundle with the fixtures (`deploy/docker-compose.mock.yml`, `127.0.0.1:4010`), against which lumea, the desktop and the web develop without the backend.
- **OKF** — Open Knowledge Format: the format of the `docs/` bundle, with fixed homes and per-doc frontmatter.
- [pairing code](standards/code/server-mcp-e-dispositivos.md#device-credential) — A 6-character code (`K7Q-4MX`, without ambiguous characters), valid for 10 minutes and single use, that the web generates with the QR link and the app exchanges for a device credential at `POST /devices/pair`; the database stores only the HMAC. pt-BR UI label: "Código de pareamento".
- [participant](standards/code/frontend-web.md#people-search-and-collections) — A directory person linked to a speaker of the recording; the library's Participants filter matches company, area and person tag of the same participant. pt-BR UI label: "Participante".
- [PAT](standards/code/server-nucleo.md#authentication) — Personal Access Token (on screen, access token): a personal `eclp_` token with scopes, stored as a hash, used by lumea and assistants (MCP) to reach the API; the desktop and the phone use the device credential.
- [person](standards/code/server-nucleo.md) — An entry in the user's directory to which the speakers of transcripts are linked; the basis of lumea's `person=` filter. pt-BR UI label: "Pessoa".
- [person tag](standards/code/frontend-web.md#people-search-and-collections) — A free label on a directory person (such as "cliente" or "diretoria"), separate from the recordings' tags; it filters the library by participants. pt-BR UI label: "Tag de pessoa".
- [pillar](standards/code/monorepo.md) — One of the monorepo's top-level folders with its own toolchain: `server/`, `worker-gpu/`, `engines/`, `web/`, `desktop/`, `mobile/`, `contracts/`, `deploy/`.
- [pipeline step](standards/code/processamento-automatico.md) — One of the six processing steps of a recording per revision (received, preprocessing, transcription, agenda type, fields, summary), with state `pending`, `active`, `done`, `failed` or `skipped`.
- [platform secret](standards/code/server-admin.md) — A sensitive value (`hf_token`, `anthropic_api_key`) of `platform_secrets`, stored encrypted through the admin panel, write-only: the API never returns it; the Hugging Face token lives under Speakers and the Anthropic key under Agents.
- [platform settings](standards/code/server-admin.md) — The single `platform_settings` row that the admin edits (transcription, speakers, voice, preprocessing) and that applies to all accounts.
- [preprocessing](standards/api/jobs-transcricao.md#preprocessing) — Audio treatment by the GPU worker before ASR, configured by the admin: 16 kHz mono, noise reduction (RNNoise), loudness normalization, trimming of leading and trailing silence and channel separation.
- [provider](standards/code/server-agentes.md#providers) — Access to a language model (`claude-cli`, `anthropic`, `openai-compatible` or `ollama`) that the admin registers on the platform and marks with the purposes.
- [purpose](standards/code/server-agentes.md#provider-routes-and-the-boundary-with-the-admin-panel) — A use of a provider (`used_for`): `summaries`, `fields`, `chat` or `agenda_detection`; each purpose has at most one provider.
- [quality gate](standards/code/monorepo.md) — The proof of the nine pillars on the GPU host (`bash deploy/gate.sh`) that publishes the `eclume/gate` status on the commit; deploys and releases refuse a SHA without it in `success`.
- [recent panel](standards/code/desktop-interface.md#painel-recentes) — The top of the desktop main window with the account's last N recordings (Ocultar, 3, 5 or 10; 5 by default), the step and progress of each, the "Precisa de você" alert and Copiar resumo. pt-BR UI label: "Recentes".
- [recording reference](standards/code/desktop-pasta-sincronizada.md#layout) — The first 8 characters of a recording's id ("ref. 01928f3a"), shown under the title in eclume web and used as the file-name suffix in the desktop's synced folder, to link a file to its recording. pt-BR UI label: "ref.".
- [recording service (Android)](standards/code/mobile-app.md#plugin-nativo-e-serviço-em-primeiro-plano) — The microphone-type foreground service of the mobile app, with the ongoing notification (Pausar, Marcador, Parar), which keeps recording with the screen locked.
- [recording start](standards/code/formato-audio-upload.md#the-recording-start-read-before-the-conversion) — The `recorded_at` of an imported recording, read from the file metadata before conversion and confirmed by the person in the Import modal.
- [RLS](standards/code/server-nucleo.md) — Postgres Row-Level Security: the per-owner policies (`app.user_id`) that isolate eclume's data under the `eclume_app` role.
- [scope](standards/api/contrato-v1.md#conventions) — A token permission (`recordings:read`, `summaries:write`, `people:read`…) that each API route and each MCP server tool requires.
- [scope group](standards/code/server-mcp-e-dispositivos.md#scope-groups-of-the-mcp-connection-screen) — A set of scopes that the MCP Connection screen offers as a single choice: Buscar e ler gravações, Ler e editar resumos, Editar campos e tags and Excluir gravações. pt-BR UI labels: as listed.
- [server descriptor](standards/code/server-mcp-e-dispositivos.md#server-descriptor) — Public `GET /api/v1/server`: name, address, MCP address, root CA fingerprint and versions; the source of mDNS, the QR, pairing and the installer with an embedded address.
- [server state](standards/code/frontend-web.md) — How the web names the recording on the server (Na fila, the step in progress, Pronta, Falhou, Cancelada); "Na fila" is only the wait for transcription. pt-BR UI labels: as listed.
- [silence stop](standards/code/desktop-gravacao.md#nota-de-voz-e-parada-por-silêncio) — The automatic end of a voice note after 2, 4 or 8 s without speech, decided by the desktop app's energy detector; with no voice in the first 10 s, the note is discarded. pt-BR UI label: "Parada por silêncio".
- [skill](standards/code/server-agentes.md#agent) — Reusable instructions of the person for the Agent (name `/name`, description, Markdown instructions and, optionally, the allowed tools), registered under Skills (`/agente/habilidades`) and invoked by `/name`, by the picker or by the Agent itself with `use_skill`. pt-BR UI label: "Habilidade".
- [speaker](standards/code/server-nucleo.md#people-collections-and-transcript-editing) — A distinct voice that diarization separates in a transcript ("Locutor 1"), linked to a directory person by hand or by voice identification. pt-BR UI label: "Locutor".
- [speaker naming](standards/code/processamento-automatico.md#speaker-naming) — An account preference (`require_speaker_naming`, at `/me/speaker-naming`) that makes ingestion stop at the `speakers` step until every speaker with relevant speech has a person; see awaiting speakers. pt-BR UI label: "Marcação dos locutores".
- **spec** — A unit of work of the Quenching cycle, stored as a GitHub issue and driven by `develop` → `execute` → `conclude`.
- [step reason](standards/code/processamento-automatico.md) — A code (`reason`) the server writes on a skipped step (`no_provider`, `no_types`, `cancelled`…), shown as visible text under the step bar by the shared vocabulary's `MOTIVOS`.
- [subject rule](standards/code/processamento-automatico.md#agenda-types) — The rule (`title_instructions`) the agent follows to write the `{assunto}` of a recording's title, defined on each agenda type; empty, the fallback type's applies.
- [summary version](standards/code/server-agentes.md#versions-and-editing) — Each state of a transcript's summary, numbered per transcript and with origin `generated` (agent), `manual` (hand edit or revert to the generated one) or `chat`; the current one is the highest-numbered completed.
- [synced folder](standards/code/desktop-pasta-sincronizada.md) — A computer folder that the desktop app keeps as a mirror of the library: each recording's current summary in Markdown and the transcript in JSONL, one subfolder per collection and an `AGENTS.md` at the root, to serve as an Obsidian vault and an agent working folder. pt-BR UI label: "Pasta sincronizada".
- [tag registry](standards/code/processamento-automatico.md#tag-registry) — Each account's list of tags, with a "when to use" description for each: by default the agent only chooses among them (fixed tags); in self-managed mode it creates a few new ones, with a per-recording limit and a registry cap. pt-BR UI label: "Tags".
- [title pattern](standards/code/processamento-automatico.md) — The title template an agenda type applies to the recording, with the placeholders `{assunto}`, `{data}`, `{tipo}` and `{<field key>}`. pt-BR UI label: "Padrão de título".
- [transcript revision](standards/code/processamento-automatico.md#the-pipeline-per-revision) — Each transcription of a recording, numbered (`transcription_jobs.revision`): retranscribing opens a new revision and redoes the pipeline chain, whose steps count per revision.
- [updater](standards/code/desktop-distribuicao.md) — Automatic update of the desktop app through the Tauri plugin: reads `latest.json` at `/downloads/` of the eclume server and only installs the package signed with eclume's minisign key.
- [value origin](standards/code/processamento-automatico.md) — Where a field's value came from: `auto` (the agent), `edited` (the user wrote it) or `accepted` (the user accepted the automatic one); automatic filling never overwrites the last two.
- [voice note](standards/code/server-nucleo.md#recording-date-kind-and-markers) — A recording of `kind: note` (a person dictating an idea or reminder), which goes through the same pipeline as the meeting (`kind: meeting`); it is the term of the screen, the desktop and MCP. pt-BR UI label: "Nota de voz".
- [voice suggestion](standards/code/identificacao-por-voz.md) — A person proposed for a speaker with no person when the voice passes the platform threshold but not the account's assignment one; it only becomes a link when someone accepts.
- [voiceprint](standards/code/identificacao-por-voz.md) — A set of a person's samples (embeddings of speakers confirmed as them, from the same model as diarization), compared by centroid to suggest them in new transcripts; sensitive biometric data under LGPD, only with identification on at the platform and only among the owner's people.
- [WhisperX](project/referencias.md) — An ASR library (batched faster-whisper, word alignment, pyannote diarization) used as the engine in the GPU worker.
