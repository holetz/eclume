# File import in the desktop app

The app imports a recording made outside it (a recorder, a phone, a meeting's recording) and puts
it in the same queue as its own. The person's file is never touched: the app reads it, converts a
copy and uploads it. The pure part lives in the `eclume-import` crate (`desktop/crates/import`),
tested with fixtures generated by ffmpeg (`tests/fixtures/generate.sh`); the app
(`src-tauri/src/import.rs`) wires the dialog, the events and the queue.

## Input

- "Importar arquivo…" (window, tray and `Ctrl/⌘+O`) calls `pick_import_file`, the native dialog
  of `tauri-plugin-dialog` opened in Rust, with the "Áudio e vídeo" filter (the 20 formats of
  `import::EXTENSIONS`).
- Dragging onto the **window** arrives through `WindowEvent::DragDrop`, which emits
  `import-dropped` with the path. The window has no file API: it only receives paths from Rust.
  The tray or Dock icon does not receive files.

## Reading (`probe`)

`probe_import(path)` returns `{duration_ms, has_audio, decodable, recorded_at, date_origin}`
without decoding the audio. The recording date comes, in this order of trust:

| Order | Source | `date_origin` |
|---|---|---|
| 1 | MP4, MOV and M4A: the `creation_time` of `moov/mvhd`, read by `mp4date.rs` with no dependency (versions 0 and 1, 1904 epoch); zero or before 1990 does not count | `mvhd` |
| 2 | `symphonia` date tags (`RecordingDate`, `Date`, `OriginalDate`: ID3 `TDRC`/`TYER`, Vorbis `DATE`, MP4 `©day`), only with a full day | `tag` |
| 3 | the file's modification date minus the duration (the likely start) | `file_mtime` |

- The "Importar um arquivo" screen shows the name, the duration and the "Gravado em" field in local
  time, with the `.date-source`: "lida do arquivo" (1 and 2) or "data de modificação do arquivo;
  confira" (3).
- Confirming without changes sends `recorded_at_source: file_metadata`; changing it sends `user`.
  That is the contract's semantics (holetz/eclume#34): read from the file and confirmed at import.
- A file with no sound track is refused before the conversion.

## Conversion (`convert`)

- **Decoding.** `symphonia` 0.5 (pure Rust, MPL-2.0, unmodified) decodes MP3, AAC, ALAC, FLAC,
  Vorbis and PCM, in the MP4/MOV/M4A, MKV/WebM, Ogg and WAV containers. Opus inside WebM and Ogg,
  which `symphonia` only demuxes, goes to the libopus of the `opus` crate the recorder already
  brings. Video is ignored.
- **Encoding.** Downmix to mono, the recorder's `Mixer` (the workspace resampler) down to
  16 kHz and the recorder's `OggOpusWriter` at **32 kbps**, the browser's bitrate
  ([formato-audio-upload.md](formato-audio-upload.md)). The output is `gravacoes/<id>.ogg`
  (written as `.part` and renamed at the end), with progress through the `import-progress` event
  (0 to 1).
- **Fallback.** A codec or container `symphonia` does not read (AVI, AC-3, WMA, AMR) is **copied**
  as is to `gravacoes/<id>.<ext>`, with the `content_type` from the extension. The server accepts
  `audio/*` and `video/*`, and the worker decodes with ffmpeg.
- **Decoder panic:** the conversion runs in `catch_unwind`; a file that makes `symphonia` panic
  counts as a file that does not decode: the `.part` goes away and the fallback applies (it goes
  as is). The import in progress is switched off by a guard, even after the panic.
- **Cancel** (`cancel_import`) interrupts between packets and deletes the partial file. The end
  comes out through `import-finished` (the id in the queue) or `import-failed` (the error text).

Why convert in the app: a meeting video is GBs, and the audio that matters, ~14 MB/h. The server
gets the same format as from the browser and the desktop. Why `symphonia` and not an embedded
ffmpeg: one ffmpeg per platform adds ~80 MB, requires `externalBin` with a universal binary on
macOS and brings LGPL/GPL depending on the build; `symphonia` compiles under `cargo xwin` and
covers the formats of the browser fixtures, except AVI, which falls to the fallback.

Why copy instead of pointing at the original: retention deletes files from `gravacoes/`, and the
person's file can never be deleted. The copy also survives if they move or delete the original
before the upload.

## Entry into the queue

`queue.begin_import` creates the row already `pending` ([desktop-gravacao.md](desktop-gravacao.md),
queue v3), with `source = 'upload'`, `kind = 'meeting'`, the confirmed `recorded_at` and origin, the
`original_name` (the name without extension) and the `content_type` only when the file was copied
(null means Ogg/Opus). The upload sends `filename` `<original_name>.<extensão do arquivo enviado>`,
so the title derives from it, and the window queue shows "kickoff-guion · 47 min".
