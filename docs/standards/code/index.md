# `standards/code/`

**How the eclume code is organized and verified** — the monorepo layout, each pillar's toolchain
and the build, lint and test commands that specs cite in `verify:`.

* [monorepo.md](monorepo.md) — pillars at the root, uv workspace, npm in `web/`, cargo workspace in `desktop/`, the mobile app in `mobile/`, and the commands of each one
* [formato-audio-upload.md](formato-audio-upload.md) — the Opus mono 16 kHz in Ogg format the browser produces before upload, the engines (WebCodecs/Mediabunny and ffmpeg.wasm) and the API of `web/src/lib/media-convert`
* [desktop-gravacao.md](desktop-gravacao.md) — how the desktop app records (mic + system in Ogg/Opus mono 16 kHz), the voice note with silence stop, the markers, the SQLite v4 queue and the sync and detection traits
* [desktop-distribuicao.md](desktop-distribuicao.md) — how the desktop app becomes installers (tag `desktop-v*`, release on the host through `deploy/release-desktop.sh` or the `desktop-release` workflow, server embedded in the build), updates itself through the updater with its own minisign key, announces "Atualizado para X" (Updated to X) and is published in `/srv/eclume/downloads`
* [desktop-interface.md](desktop-interface.md) — the desktop app's window and tray in the Design System: framework-free ES modules, `eclume.css` identical to the web's, CSP without inline style, views, theme, global and window shortcuts, help menu and the Playwright tests with a simulated Tauri
* [desktop-pasta-sincronizada.md](desktop-pasta-sincronizada.md) — how the desktop app mirrors the library into a local folder (summaries in Markdown, transcripts in JSONL, one subfolder per Collection, `AGENTS.md`, manifest), to serve as an Obsidian vault and an agent folder
* [desktop-importacao.md](desktop-importacao.md) — how the desktop app imports a file: the date read from `mvhd`, from the tags or from the modification time and confirmed, the conversion to Opus by `symphonia` and the fallback of copying the original
* [server-nucleo.md](server-nucleo.md) — how the server persists and isolates (SQL migrations, RLS under `eclume_app`), authenticates (session with CSRF, PAT), receives uploads (part URL signed by the API) and is tested (real services, conformance with the OpenAPI)
* [server-agentes.md](server-agentes.md) — how the server talks to agents: providers (`claude -p` without tools, Anthropic, OpenAI-compatible, Ollama only with the GPU free) with one purpose each, encrypted keys, summaries by the agenda type's instructions, the `summarize` job and the map-reduce
* [processamento-automatico.md](processamento-automatico.md) — what happens after the upload: the six pipeline steps per revision, fields with rules and the value origin, agenda types and the admin's defaults, the `fill_fields` and `detect_agenda_type` jobs, the summary by type and the previews
* [frontend-web.md](frontend-web.md) — the web app: client generated from the contract, single origin with session and CSRF, folder structure, admin panel outside the user's session, grouped navigation, help drawer, multipart upload engine and tests (vitest over the fixtures and E2E against the mock)
* [web-central-de-ajuda.md](web-central-de-ajuda.md) — the web help center: Markdown articles with a header in the build, six topics, page keys, accent-insensitive local search, per-page drawer, inline hints, writing rules and the review of the articles when a screen changes
* [web-design-system.md](web-design-system.md) — the eclume Design System in the web: `eclume.css` generated from `design-system/styles.css`, product `app.css`, local fonts, Lucide icons, theme by `data-theme`, the flow of a visual change and the map of the old tokens
* [mobile-app.md](mobile-app.md) — the mobile app (Tauri 2, Android): the core over the desktop crates, the native plugin through the JNI bridge, the connection with the pinned CA, the eclume network, the session with audio time and markers, the sync, the screens and the proof on the emulator
* [mobile-distribuicao.md](mobile-distribuicao.md) — how the mobile app becomes a signed APK (tag `mobile-v*`, release on the host by `deploy/release-movel.sh`, keystore only on the host and versioned certificate), the `movel.json`, the publication in `/srv/eclume/downloads/movel` and the in-app update
* [desktop-deteccao-e-sync.md](desktop-deteccao-e-sync.md) — how the desktop app detects meetings (mic, process and window, with debounce and per-app policies), joins the server (first run, mDNS, pinned CA, device credential) and uploads the recordings through the resumable upload, with retention
* [server-mcp-e-dispositivos.md](server-mcp-e-dispositivos.md) — the MCP server at `/mcp` (stateless, Bearer `eclp_`, tools × scopes), the scope groups of the MCP Connection, the device credential by login or pairing code with the QR, the attempt limit, the `/server` descriptor with the CA fingerprint and the mDNS discovery
* [server-admin.md](server-admin.md) — the admin panel in the server: separate admin account and session, platform settings delivered to the worker through the `options`, write-only encrypted secrets, users with activate and deactivate, the health with the GPU worker heartbeat and the admin accounts CLI
* [identificacao-por-voz.md](identificacao-por-voz.md) — the voice suggestion of people: voiceprint as samples of confirmed speakers, centroid and threshold calibrated at ingest, retranscription that preserves links, only among the owner's people, and the LGPD regime (platform on-off switch, acceptance of the notice at sign-up instead of per-person consent, forget the voice)
* [versionamento.md](versionamento.md) — the three version lines (product, desktop, phone) and the contract on its own, the `deploy/versao.py` that moves and checks them, when each one goes up, the CHANGELOG with the "Para quem hospeda" (For self-hosters) block, the release notes and the `v<versão>` tag at deploy
